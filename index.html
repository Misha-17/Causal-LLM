Causal reasoning · CLadder v1.5

Can language models tell cause from correlation?

Suppose people who use an AI assistant finish more of their tasks. Does the assistant help? Or did they have easier tasks to begin with? The numbers alone can’t tell you. You have to reason about cause and effect. We tested how well language models do this.

A test with known answers

CLadder is a set of 10,112 yes/no questions about cause and effect. Each question describes a small, made-up world. It says which factors affect which, and it gives some probabilities. The right answer follows from the math, so it is known for certain. The model sees the description and the question. It never sees the answer. Half the answers are yes and half are no, so random guessing scores 50%.

Example

Task difficulty affects whether people use the assistant. Difficulty and the assistant both affect whether a task gets done. Half the tasks are easy. With the assistant, 90% of easy tasks and 60% of hard tasks get done. Without it, 80% and 40% do.

Question: Does using the assistant raise the chance that a task gets done?

Answer: Yes. Compare easy tasks with easy tasks and hard with hard, then average. With the assistant, 75% of tasks get done. Without it, 60% do. Full calculation.

The name CLadder comes from the “ladder of causation,” an idea from the computer scientist Judea Pearl. The ladder has three rungs. Each rung asks a different kind of question.

Claude Opus 5.5 answers 97.20% of the questions correctly. Gemini Argon scores 95.67% and GPT-6.1 Sol scores 94.36%. In the original 2023 paper, GPT-4 scored 62.03%, or 70.40% with a step-by-step prompt.

Do the results hold on new questions?

Details

Public test questions can end up in the data a model learns from. A new batch of questions, with the same ten question types, checks whether the results carry over. We tested GPT-5.5 and Claude Opus 4.8 on it.

GPT-5.5 scores 92.87% and Opus 4.8 scores 90.00%. Both are a little below their scores on the public test (95.09% and 91.39%). Their order stays the same. GPT-5.5 leads on every rung, and its lead grows at each step up: 0.40 points, then 2.22, then 5.44.

Where do the models go wrong?

Details

On the new batch, both models handle confounder questions well and collider questions badly.

A confounder is a factor that affects both the action and the outcome. Task difficulty in the example above is one. The fix is to compare like with like, which is called backdoor adjustment. Both models got every one of these questions right.

A collider works the other way: two factors both cause it. Suppose a college admits students who are strong at sport or strong at their studies, and the two skills are unrelated in general. Among admitted students, athletes will tend to have lower grades. The link appears only because we looked at admitted students. On collider questions, both models score below 60%, not far above guessing.

A separate review read the reasoning behind wrong answers from Claude Sonnet 4.6 and Gemini 2.5 Flash. Three mistakes stood out. The reasoning looks right, but the final answer is flipped. The model says an effect raises the outcome when it lowers it, or the reverse. Or it adjusts for a factor it should leave alone.

A model can score 90% overall and still get collider questions right only slightly more than half the time.

1. What CLadder measures

CLadder tests whether a model can reason from a causal story it is given. The story says which factors cause which and supplies the numbers. CLadder does not ask the model to find causes in raw data.

A program writes the questions. It builds a small causal world, phrases a question about it in plain English, and computes the right answer with formulas. The model being tested plays no part in setting the answers.

The balanced version 1.5 has 10,112 questions: 3,160 on association (rung 1), 3,160 on intervention (rung 2), and 3,792 on counterfactuals (rung 3). Exactly 5,056 answers are yes and 5,056 are no. A random yes/no guess scores 50% on average.

Use the authors’ corrected file on Hugging Face, full_v1.5_default.csv. Its prompt column holds the full question. A file with a similar name, test-balanced-v1.5.csv, leaves the question out of that column. Load the corrected file by name, and don’t mix files from different versions.

2. The math behind the three rungs

Let X be assistant use and Y task completion. 1 means yes and 0 means no. Each rung asks for a different quantity.

Rung 1, association: P(Y = 1 | X = 1) Among tasks where people used the assistant, what share got done? Rung 2, intervention: P(Y = 1 | do(X = 1)) If we made everyone use the assistant, what share of tasks would get done? The do( ) means we set X ourselves instead of only watching it. Rung 3, counterfactual: P(Y₁ = 1 | X = 0, Y = 0) Among tasks done without the assistant that failed, what share would have succeeded with it? Y₁ is the outcome had X been 1.

A structural causal model describes a world as a set of rules. It has four parts: background factors U that we don’t observe, observed variables V, rules F, and a probability distribution over the background factors, P(U). A rule sets each observed variable from its direct causes, Paⱼ, and its own background factors, Uⱼ:

𝓜 = (U, V, F, P(U)) Vⱼ = fⱼ(Paⱼ, Uⱼ)

An intervention swaps the rule for X with a fixed value, X := x. Arrows into X disappear. Every other rule stays the same. This is not the same as picking out the cases where X already equals x. Those cases may differ in other ways, such as task difficulty.

Worked example: adjusting for a confounder

Suppose task difficulty Z affects both assistant use and completion. Z is then a confounder. To remove its effect, compare outcomes within each difficulty level. Then average, weighting each level by its share of all tasks. When Z is a valid adjustment set, this is the backdoor adjustment formula:

P(Y = 1 | do(X = x)) = Σz P(Y = 1 | X = x, Z = z) P(Z = z)

Now add numbers. Half the tasks are easy and half are hard. With the assistant, 90% of easy tasks and 60% of hard tasks get done. Without it, 80% and 40% do.

With assistant: 0.90 × 0.50 + 0.60 × 0.50 = 0.75 Without assistant: 0.80 × 0.50 + 0.40 × 0.50 = 0.60 ATE = E[Y | do(X = 1)] − E[Y | do(X = 0)] = 0.15

The assistant raises completion by 15 percentage points on average. This number is the average treatment effect (ATE). The calculation holds only if Z is the right factor to adjust for. Both easy and hard tasks must also occur with and without the assistant.

Adjusting for the wrong factor can add bias. A collider is a factor that two others both cause. Filtering or adjusting on a collider can create a link between its causes where none exists.

Computing a counterfactual

A counterfactual takes three steps.

  1. Abduction (work backward). Use what you observed, E = e, to update your beliefs about the background factors. P(U) becomes P(U | E = e).
  2. Action. Replace the rule for X with X := x. Call the new model 𝓜ₓ.
  3. Prediction. Compute the outcome in 𝓜ₓ, using the updated background factors.
P(Yₓ = y | E = e) = Σᵤ 𝟙[Y under 𝓜ₓ with U = u equals y] P(U = u | E = e)

𝟙[ ] equals 1 when the statement inside is true and 0 when it is false. For continuous background factors, the sum becomes an integral. A graph and some probabilities don’t always fix one answer to a counterfactual question. CLadder only includes questions where the given information is enough.

3. How we scored the models

For each question qᵢ, the model gives an answer âᵢ. It never sees the correct answer aᵢ, the reference reasoning, or any hidden labels. We score only the final yes or no:

Accuracy (%) = 100 × (number of correct answers) / (number of questions evaluated)

Rung and question-type scores use their own question counts. The overall score counts each question once. Rung 3 has more questions than the other two, so the overall score is not the plain average of the three rung scores.

The earlier run covered seven models: GPT-5.5, Grok 4.20, Claude Opus 4.8, Claude Sonnet 4.6, DeepSeek V3.2, Gemini 2.5 Flash and GPT-5.4 Nano. Each model got all 10,112 questions through OpenRouter, a service that passes requests on to many model providers. All seven used CausalCoT prompting.

CausalCoT asks the model to solve each problem in six steps:

  1. Pull the causal graph out of the text.
  2. Name the type of question.
  3. Write the question as a formula.
  4. List the probabilities given.
  5. Work out which formula answers the question.
  6. Calculate the answer.

The original paper also used a second turn to pull out the final answer. Asking for these steps does not mean the model follows them correctly.

Models and reasoning settings differ between runs. The original paper’s rows use gpt-4-1106-preview at temperature 0 (minimal randomness). No comparison on this page isolates the effect of extra reasoning alone.

6. Error analysis

A separate review read the reasoning behind wrong answers from Claude Sonnet 4.6 and Gemini 2.5 Flash on the public test. It flags three patterns:

  • Answer flip. The reasoning looks right, but the final yes or no is wrong.
  • Direction error. The model says an effect raises the outcome when it lowers it, or the reverse.
  • Adjustment confusion. The model mixes valid adjustment for a confounder with adjustment that adds bias.

Follow-up: does making Opus 4.8 think more help?

In the first run, Opus 4.8 returned no visible reasoning on 4,608 of 10,105 questions. That does not prove it did no reasoning. We reran those 4,608 questions with a minimum thinking budget of 1,024 tokens. Accuracy on them rose from 88.60% to 90.23%.

The rerun fixed 114 answers and broke 39. That is a net gain of 75 answers, about 1.63 points across the 4,608 questions. These figures use a different question count from the main table.

7. Open questions

The old and new runs differ in model, prompt, and reasoning settings. Their scores show how each setup performed. They can’t tell us which change caused the improvement.

What to test next

  • Reworded versions of the same question, with the same answer. Does the model give the same answer?
  • Separate checks for each step: reading the graph, choosing the formula, doing the arithmetic, and giving the final yes or no.
  • The same questions at different reasoning budgets, to measure what extra thinking adds.
  • Questions the given information cannot answer. Does the model notice that the effect can’t be worked out?

These are proposals. We have not run them yet.

Key terms

Causal reasoning
Working out what causes what, and what would happen if something changed.
Rung
One of three levels of causal question: association (seeing), intervention (doing), and counterfactual (imagining).
Confounder
A factor that affects both the action and the outcome. Task difficulty is a confounder if it affects both assistant use and task completion.
Backdoor adjustment
Removing a confounder’s effect by comparing like with like, for example easy tasks with easy tasks, then averaging.
Collider
A factor that two others both cause. Filtering on it can create a false link between them.
Mediator
A middle step between an action and an outcome. The assistant might save time, and the saved time might lead to more finished tasks.
Percentage point
The plain difference between two percentages. 92% and 87% are 5 points apart.
Token and thinking budget
A token is a word or part of a word. The thinking budget is how many tokens a model may write while it works through a problem, before it answers.
